# Stored procedure review — 2026-09-10

## Outcome

The six supplied procedures use syntax supported by SQL Server 2019, but they are not ready for blind replacement in production. Static review found one public input-injection path in the Fastify query construction, one confirmed SADCP SQL syntax failure, and several result-correctness and performance risks. No production SQL was changed.

## Findings

| Severity | Finding | Evidence / impact | Recommended slice |
|---|---|---|---|
| Critical | `mean_threshold` reaches a raw `EXEC` string without numeric validation | The public schema accepts a string and `apirest.mjs` interpolates it. This is exploitable before the stored procedure is entered. | Validate and bind/normalize this value in a small application hotfix. |
| High | `sadcpavg` has a trailing comma in one order branch | `ORDER BY longitude DESC, latitude DESC,` fails for `xorder=-1`, `yorder=-1`. A minimal production read returned an empty HTTP 200 while SQL Server logged error 102. | Correct the comma in a versioned candidate procedure; add a four-direction order matrix test. |
| High | SQL errors during streaming can appear as HTTP 200 with an empty/truncated body | Headers are sent before a later SQL stream error can change status. Consumers cannot distinguish this from valid output. | Buffer until the first row/error or redesign the streaming error contract; add a deliberate DB-error integration test. |
| High | `TOP(@limit)` is selected before the final dynamic `ORDER BY` | The database chooses an arbitrary subset and sorts only that subset. Results can change between plans/runs. | Move limiting after deterministic ordering and compare old/new result sets. |
| Medium | Ordering lacks stable tie-breakers | Longitude/latitude alone do not order rows sharing a cell across depth/time. | Add documented tie-breakers appropriate to each response shape. |
| Medium | SADCP accepts numeric `dep_mode` but sends `NULL` | Public contract accepts values such as `5`; application dispatch only applies numeric depth bins for CTD. | Decide whether to reject it for SADCP or implement it; do not silently ignore it. |
| Medium | CTD default-depth branch uses `@mode != 'raw'` | With `@mode = NULL`, SQL three-valued logic skips the documented default `@depas=10`. | Characterize current payloads before changing compatibility-sensitive behavior. |
| Medium | One `ctdavg` path constructs but does not append `@having` | `mean_threshold` is silently ignored outside the grouped branches. | Add result-set tests for every `dep_mode`/threshold combination before correction. |
| Medium | Monthly date filtering computes a date expression per row | The expression over `[year]`/`[month]` is non-sargable and can prevent ordinary index seeks. | Compare plans for an integer `year*100+month` range after collecting indexes/statistics. |
| Medium | Pre-aggregated means are averaged without `data_no` weighting | Unequal source sample counts can bias combined CTD/SADCP means. | Confirm scientific intent; compare weighted and unweighted results on known cells. |
| Medium | Bare `numeric` parameters imply `numeric(18,0)` | Fractional depth inputs allowed by the API may be rounded. | Decide and declare the intended scale before altering procedure signatures. |
| Low | Dynamic `append`/`cruise` remain unsafe for direct DB callers | The public app currently whitelists `append` and disables `cruise`/raw paths, but the DB boundary is not self-defending. | Validate identifiers inside procedures or replace dynamic projection with fixed branches. |

## Compatibility and evidence limits

The reviewed T-SQL constructs are available on SQL Server 2019. Server version alone is insufficient: database `compatibility_level`, view definitions, base-table indexes, statistics freshness, row counts, and actual execution plans determine real behavior. The supplied screenshots are useful orientation but cannot establish those facts. Run `diagnostics/sqlserver-2019-readonly.sql` and retain its result sets with this review.

The raw procedures (`ctdqry`, `sadcpqry`) are currently unreachable from the public API because raw and cruise modes are blocked. Their risks still matter to direct database callers but are lower priority than `ctdavg`, `ctdgridqry`, `sadcpavg`, and `sadcpgridqry`.

## Safe validation order

1. Apply the application-only `mean_threshold` validation fix and regression test.
2. Capture the read-only database diagnostics and actual plans for small, representative calls.
3. Create candidate procedures under new names in a non-production database; never overwrite the production names for exploratory testing.
4. Fix only the SADCP trailing comma and verify the order-direction matrix plus byte-level payload compatibility.
5. Separately test deterministic `ORDER BY`/`TOP`, date sargability, depth defaults, and weighted means. Each changes semantics and needs its own result comparison.
6. Promote one reviewed change at a time with scripted backup and rollback.
